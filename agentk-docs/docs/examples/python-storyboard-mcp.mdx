# Python 示例：用 MCP Tool 生成分镜短片

这个完整示例展示另一种消费形态：Python Worker 向 AgentK 发布 Storyboard <Capability />；
Python MCP Server 使用 AgentK Client SDK 启动 <Pipeline />，再把结果包装成
`generate_storyboard_film` <Tool />。支持 MCP Apps 的 Host 可以内嵌最终视频播放器。

## Storyboard Film 是什么

调用方提供短片主题和镜头数，Workflow 依次完成：

```text
主题
  → 生成分镜列表
  → 为每个分镜生成首帧
  → 并行生成视频片段
  → 拼接成功片段
  → 返回 Video Artifact
```

它不是 AgentK 内置产品能力，而是独立 Worker 提供的示例 Capability。这个业务包含多模型调用、
分钟级执行、并行分支、局部失败、进度和最终 <Artifact />，适合展示 Worker 与下游应用之间的
完整边界。

:::warning[模型调用费用]

示例会实际调用文本、图片和视频生成能力，可能需要数分钟并产生费用。首次运行请使用
`shots: 1`。

:::

## 运行链路

```text
MCP Host
  → Python MCP Server
  → AgentK Python Client SDK
  → Session + Pipeline Execution
  → Python Storyboard Worker
  → Text / Image / Video / Concat Capability
  → Pipeline Output
  → MCP App Player
```

示例由两个独立进程组成：

- `python/worker` 是能力提供方，实现 Workflow、Schema、Capability 发布和进度上报；
- `python/mcp-server` 是下游应用，使用已登记的工作负载 KSN 接入 AgentK，并提供 MCP Tool 与
  UI Resource。

MCP Client 只访问 MCP Server；AgentK Session、Execution 和接入身份均由 MCP Server 管理。

## 共享业务契约

Python 与 Go Worker 遵循同一 Storyboard ABI，但使用不同的 Capability ID 和 task queue：

```text
Capability ID:  contrib.storyboard_example.storyboard_film_python
Task Queue:     contrib.storyboard-example-py
```

MCP Tool 只要求调用者填写 `topic` 和 `shots`。MCP Server 在服务端补充模型选择，再启动
完整 Pipeline：

```json
{
  "topic": "雨夜里走过霓虹街道的猫",
  "shots": 1,
  "chatModel": "deepseek-v4-pro",
  "imageModel": "z-image-turbo",
  "videoModel": "kling-3.0"
}
```

成功输出包含一个视频 Artifact 和成功片段数。

## Worker：连接、注册与发布

`python/worker/worker.py` 使用 Worker SDK 连接 AgentK Temporal namespace。下面保留实际 import
路径：

```python title="python/worker/worker.py"
from datetime import timedelta

from abi import (
    CAPABILITY_ID,
    WORKER_TASK_QUEUE,
    WORKFLOW_TYPE,
    StoryboardInput,
    StoryboardOutput,
)
from agentk.worker import Capability, Tool, Worker, connect_temporal
from temporalio.contrib.pydantic import pydantic_data_converter
from workflow import StoryboardFilmExample

client = await connect_temporal(
    data_converter=pydantic_data_converter,
)
worker = Worker(
    client,
    task_queue=WORKER_TASK_QUEUE,
    workflows=[StoryboardFilmExample],
)
```

`connect_temporal` 通过 KESS 发现服务，Worker 不配置 Temporal 地址或 namespace。
`Worker` 保留 Temporal Python SDK 的原生注册方式，并增加 Capability 发布与 invocation context。

Pydantic Model 生成公开 Schema：

```python
worker.publish_workflow(
    Capability(
        id=CAPABILITY_ID,
        temporal_type=WORKFLOW_TYPE,
        description=PIPELINE_DESCRIPTION,
        input_schema=StoryboardInput.model_json_schema(),
        output_schema=StoryboardOutput.model_json_schema(),
        timeout=timedelta(hours=24),
        tool=Tool(),
    )
)
```

`Tool()` 将 Workflow 同时暴露为 blocking Tool。Pipeline 不需要额外发布声明。

## Workflow：组合 Capability 并上报进度

业务 Workflow 仍然是普通 Temporal Python Workflow。它使用 Worker SDK 按 Capability ID
调用 AgentK 内置能力：

```python title="python/worker/workflow.py"
from abi import (
    GENERATE_IMAGE_CAPABILITY,
    GenerateImageInput,
    GenerateImageOutput,
)
from agentk.worker import invoke_capability, report_progress

frame = await invoke_capability(
    GENERATE_IMAGE_CAPABILITY,
    GenerateImageInput(
        model=args.imageModel,
        prompt=shot.frame,
        aspectRatio="16:9",
    ),
    result_type=GenerateImageOutput,
)
```

镜头处理使用 `asyncio.gather` 并发执行。业务阶段通过 Worker SDK 上报：

```python
await report_progress(
    f"clip/{index}",
    "片段完成",
)
```

AgentK 把进度写成 `invocation_progress` Event，`invocation_id` 就是当前 `exe_...` Execution
ID。Workflow 直接运行或测试、没有 AgentK context 时，进度接口不会改变业务结果。

## MCP Server：使用 Python Client SDK

MCP Server 通过 KESS gRPC transport 创建 Client：

```python title="python/mcp-server/main.py"
from agentk.api.v1 import model_pb, profile_pb, service_pb
from agentk.client import AsyncClient, Options
from agentk.client.grpc import create_client
from protobuf import Oneof
from protobuf.wkt import struct_pb


def make_agentk_client() -> AsyncClient:
    return create_client(Options())
```

Tool 调用首先创建 Session：

```python
async with make_agentk_client() as client:
    created = await client.create_session(
        service_pb.CreateSessionRequest(
            title=f"Storyboard Film: {topic}",
            profile=profile,
        )
    )
    session_id = created.session.id
```

然后使用 Profile 中的名称启动 Pipeline Execution：

```python
started = await client.start_execution(
    service_pb.StartExecutionRequest(
        session_id=session_id,
        input=Oneof(
            "pipeline",
            service_pb.PipelineExecutionInput(
                pipeline="storyboard_film_example",
                args=struct_pb.Struct.from_python(args),
            ),
        ),
    )
)
execution_id = started.execution.id  # exe_...
```

MCP Server 使用 `GetExecution` 等待终态：

```python
fetched = await client.get_execution(
    service_pb.GetExecutionRequest(
        session_id=session_id,
        execution_id=execution_id,
    )
)
execution = fetched.execution
```

`RUNNING` 时继续等待，并把等待时间转换为 MCP Progress Notification；`COMPLETED` 时从
`execution.pipeline.output` 校验 Artifact 和 `clipCount`；`FAILED` 或 `CANCELLED` 时向 MCP
调用返回错误。

AgentK 的 invocation 进度可以通过 `WatchEvents` 提供更细的业务阶段；当前示例为了保持 MCP
等待逻辑简单，使用 `GetExecution` 轮询终态。

## MCP App：显示最终视频

播放器是一个原生 HTML/CSS/JavaScript 文件，不需要单独前端构建。MCP Server 将它注册为
`ui://storyboard-film/player.html` Resource，并把完成后的 Video Artifact 返回给 Host。

不支持 MCP Apps 的 Client 仍能收到文本和结构化结果；是否展示 Progress Notification 取决于
MCP Client 实现。

MCP Server 使用的 Profile 选择 Python Worker：

```json
{
  "defaultModel": "deepseek-v4-pro",

  "tools": [],

```

## 运行

Python Worker 和 MCP Server 使用同一个 uv workspace。先安装依赖：

```bash
cd python
uv sync --all-packages --all-extras
```

启动 Worker：

```bash
cd worker
uv run --no-sync python worker.py
```

再向 AgentK 平台维护方登记 MCP Server 的工作负载 KSN，完成 Service/App 绑定并启动服务：

```bash
cd ../mcp-server

export KWS_SERVICE_NAME='<registered-ksn>'
export MCP_HOST='0.0.0.0'
export MCP_PORT='8000'
export MCP_ALLOWED_HOST='localhost'

uv run --no-sync python main.py
```

本机 KESS 只连接 staging，不需要启动本地 Temporal 或 AgentK，也不配置 AgentK 固定 URL。
MCP Endpoint 是 `http://localhost:8000/mcp`，健康检查是
`http://localhost:8000/healthz`；这些地址属于示例 MCP Server。

## 示例边界

- MCP Endpoint 暂无入站鉴权，只能部署在可信网络；
- MCP Server 使用自身登记的 KSN 调用 AgentK，MCP Client 不接触这份工作负载身份；
- MCP Server 为每次 Tool 调用创建独立 Session；
- 当前通过 `GetExecution` 轮询终态，没有持久化调用记录；
- 生产应用应根据自身需求保存 `session_id` 和 `execution_id`。

如果需要业务 REST Job API，阅读
[Go：把 AgentK Pipeline 包装成业务 Job API](/examples/go-storyboard-job-api)。
