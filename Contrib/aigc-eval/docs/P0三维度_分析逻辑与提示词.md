# 三个 P0 维度：分析逻辑与 System Prompt 汇总（供 review）

> 目标：把「动态崩坏 / 画面异常 / 文字异常」三个 P0 维度当前的**检测链路、判定逻辑、阈值、以及完整 system prompt** 集中到一处，便于评估进一步提升点。
> 对应代码：`judge_pipeline.py`（编排/聚合）、`rubric_prompts.py`（prompt）、`integrity.py`（抽帧）。缓存版本 `CACHE_VERSION = v14`。

---

## 0. 一句话总览

三个 P0 维度都**不信任**主链路里那个"看压缩视频 + 纯文本裁决"的验证器（它对感知类缺陷普遍不敏感、且对崩坏负例过敏），
而是各自挂了一个**独立的"全片抽帧 + 专项 prompt"检测器**，其结论作为**权威信号覆盖**对应的 rubric 叶子。

| 维度 | 检测器 | 覆盖的 rubric 叶子 | 采样 | 聚合 | 当前指标(P/R/F1) |
|---|---|---|---|---|---|
| P0.1 动态崩坏 | `scan_collapse` + 自适应投票 | `dyn_collapse_major` | 全片原生帧 ≤14，运动加密 | 逐帧→整片 verdict，多票取多数 | 0.74 / 0.87 / 0.80 |
| P0.2 画面异常 | `scan_visual` | `visual_exposure_color` / `visual_greasy` | 全片帧 ≤9 | 逐帧→两类各出 verdict | 1.00 / 0.62 / 0.76 |
| P0.3 文字异常 | `scan_text` | `visual_text` | 全片原生帧 ≤12 | 逐帧→整片 verdict | 0.86 / 0.82 / 0.84 |

抗不均衡指标（正例偏多，更该看这个）：崩坏 MCC 0.27 / 平衡准确 0.62；画面异常 MCC 0.52 / 0.81；文字 MCC 0.51 / 0.76。
**→ 崩坏其实最弱（负例特异度仅 0.36），高 P/R 是被正例多数抬起来的。**

## 1. 通用机制（三维度共用）

### 1.1 抽帧（`GeminiZoomInspector._scan_frames`，基于 `integrity.plan_sample_times`）
- 用 ffmpeg `motion_profile` 得到逐帧运动量 → `plan_sample_times`：**均匀基础网格 + 高运动加密**，`extract_native_frames` 抽原生分辨率大图。
- 参数：`base_fps`（短片 1.0~1.5、长片 0.7~1.0）、`max_frames`（崩坏 14 / 视觉 9 / 文字 12）、`min_gap=0.25s`。
- 图片 token 与分辨率基本无关（512 与原生都 ~1080 token），故一律抽原生帧看细节。

### 1.2 自适应投票（仅崩坏用，`COLLAPSE_ADAPTIVE`，控成本）
- 先投 1 票；**首票结果明确**（"干净且无任何帧被标记" 或 "崩坏且有 severity≥3 一眼可见证据"）→ 直接定论；
- 只有**模糊**（unsure / 崩坏但仅 sev2 / 判干净却有帧被标记）才补票到 `COLLAPSE_VOTES=3` 取多数。
- 效果：多数 case 只花 1 票（日志 `vote=1/1`），成本≈原 1/3；明确 case 结论与 3 票一致。

### 1.3 权威覆盖（`analyze_case`，`normalize_rubric` 之后）
- 专项检测器运行过 → 用它的结论**直接改写**对应 rubric 叶子的 `verdict/severity`（可升可降），再算 hard_failures / 门控 / veto。
- 崩坏：判 collapse→`collapse_level=max(2,sev)`；判 clean→`collapse_level=0`（压掉验证器过敏）。
- 视觉：曝光/油腻各自 `violated 且 sev≥2` 才置 violated，否则 pass。
- 文字：`violated`→置 violated(sev≥2)；`not_applicable`→保持不适用；`pass`→pass。

### 1.4 开关
`JUDGE_COLLAPSE_SCAN` / `JUDGE_VISUAL_SCAN` / `JUDGE_TEXT_SCAN`（默认全开）、
`JUDGE_*_SCAN_FRAMES`、`JUDGE_COLLAPSE_VOTES`、`JUDGE_COLLAPSE_ADAPTIVE`。
注意：三个扫描目前都在 `_video_mode==native` 分支内运行。

## 2. P0.1 动态崩坏（明显崩坏）

- **判定入口**：`collapse_level >= 2` 视为"有明显崩坏"。
- **采样**：全片原生帧 ≤14（运动加密），独立于观察器 focus（避免观察器不敏感就漏抽真正崩坏帧）。
- **聚合**：每票逐帧判 collapse→整片 verdict（任一帧一眼可见崩坏即 collapse，severity 取最高）；多票取多数；自适应投票。
- **当前表现**：P0.74 R0.87 F1 0.80；**漏报** 002(熊猫融化)/010/011；**误报** 025/026/027/028/029/032/033。
- **已知问题 / 可提升点**：
  1. 负例特异度低（0.36）。误报里 025/026/032 是"模型抠出的真实但亚显著瑕疵"（写实运动模糊手、远景小主体），与真崩坏同为满票，**阈值切不开**——是标签边界问题。
  2. 收误报若靠"显著性门槛"会连带砸召回（v13 教训：召回 91→70）。
  3. 可考虑：主体面积/显著度先验、时序一致性（真崩坏常跨多帧）、让模型输出 0-100 置信分以便阈值调节。

### System Prompt：`COLLAPSE_VOTE_SYSTEM`
```
你是 Video Judge 的「明显画面崩坏」专项判定器。

给你若干张来自同一视频、按时间顺序标注了时刻的原生分辨率高清帧（覆盖全片，含快动作/运动峰值）。
你只判断一件事：**这段视频里，主体是否出现了「明显崩坏」**。

【什么是「明显崩坏」——判定基准是"正常速度观看时，普通观众一眼就能看出主体长错了"】
只要出现下列任一种、且**显著到一眼可见**，即算崩坏（severity 2=明显 / 3=严重）：
1. 主体**融化 / 粘连 / 相互熔合**：人/动物的身体互相黏成一团、或身体与坐骑/背景/物体融为一体、边界消失。
2. **肢体/手指结构错误**：手指粘连增生成爪状或肉团、指节数量明显不对、多出或缺失肢体、四肢扭曲成解剖上不可能的走向。
3. **面部/五官破碎错乱**：脸部结构塌陷、五官错位重叠、糊成无法辨认的形状。
4. **主体形态崩解**：躯干/头身比例严重畸变、主体扭曲到不成人形/兽形、结构断裂。
5. 主体在运动中**突然形变、抽搐式扭曲、部位凭空增减**。
—— 动画/卡通/非写实内容里的崩坏往往是**清晰的、边界锐利的**结构错误（如动画人物一只明显的畸形爪手、卡通角色熔成一摊），这类**尤其要抓住，不要因为"是动画风格"就放过**。

【什么不算崩坏——避免误报，与漏报同等重要】
- **主体级的融化 / 粘连 / 熔合 / 增指 / 肢体错误一定要抓**：哪怕主体在运动、在远处、在动画风格里，
  只要结构真的错了（如熊猫身体熔成一团、龙身崩解、手指粘连成爪），就算 collapse——**不要用"运动模糊/风格化"当借口放过主体崩坏**。
- 只有下列情况才判 clean：
  ①写实/实拍中，手/身体因**运动模糊、快门拖影、浅景深虚化、低分辨率**导致边界发软、手指边界糊在一起，
    但整体**仍能辨认出是一只正常的手 / 正常的身体、结构没有真的错**；
  ②正常的遮挡、透视变形、艺术夸张、本就如此的风格化造型。
- 判定前自问一次：「这是结构**真的错了**（长歪、熔了、多了少了），还是只是没拍清楚/动态模糊？」
  真的错了 → collapse；只是糊 → clean。
- 拿不准、该分辨率下无法判定 → verdict=unsure、severity=0，不要凭"有点糊"就判 collapse。

输出严格 JSON：
{
  "per_frame": [
    {"time": "00:02.4", "collapse": true, "severity": 3, "part": "掐脖的右手", "note": "手指增生粘连成爪状肉团，一眼可见结构错误"}
  ],
  "verdict": "collapse|clean|unsure",
  "severity": 0,
  "evidence": "综合结论：哪一帧、哪个部位、怎么崩的；或为何判 clean"
}

聚合规则：
- per_frame 逐帧给判断（每张图一条，用图上标注的时刻）；只要**有任意一帧**出现上述"一眼可见"的崩坏，
  整体 verdict=collapse，severity 取崩坏帧里的最高值（明显=2，严重=3）。
- 全部帧都只是运动模糊/发糊/正常 → verdict=clean、severity=0。
- 拿不准、既没有确凿崩坏也不完全干净 → verdict=unsure、severity=0。
```

## 3. P0.2 画面异常（曝光 / 颜色 / 油腻感）

- **判定入口**：`visual_exposure_color` 或 `visual_greasy` 任一 `violated 且 severity≥2`。
- **采样**：全片帧 ≤9（曝光/色彩是全局属性，不需很密）。
- **当前表现**：P1.00 R0.62 F1 0.76；负例零误报；**漏报 10 个几乎全是曝光/色彩子类**（油腻感抓得好，曝光/偏色偏保守）。
- **已知问题 / 可提升点**：
  1. 召回瓶颈在 **exposure_color 子类**——prompt 对"风格 vs 缺陷"给了很强的从宽指令，可能压过头。
  2. 可考虑：把曝光/颜色/油腻**拆成三个独立子判定**分别给证据；或引入 ffmpeg 客观量化（`signalstats` 的亮度/饱和直方图、死黑死白像素占比、帧间亮度方差）做**程序辅助信号**再交叉。
  3. 负例仅 8 个，特异度=1.0 的置信区间较宽。

### System Prompt：`VISUAL_SCAN_SYSTEM`
```
你是 Video Judge 的「画面异常」专项判定器（曝光 / 颜色 / 油腻感）。

给你若干张来自同一视频、按时间顺序标注时刻的画面帧（覆盖全片）。只判断画面**基础画质**是否异常，
**不评价** prompt 是否达成、主体结构崩坏、文字、动作等其它维度。

判定两类问题（分别给结论）：
1) 曝光 / 光影 / 颜色异常（exposure_color）：
   - 曝光：明显过曝（大片死白、高光溢出细节全失）或明显欠曝（大片死黑、暗部糊死）；帧间亮度突兀跳变、闪烁。
   - 颜色：明显偏色（整体泛某色且不合场景）、色彩失真/溢出、严重色带断层(banding)、过饱和到刺眼、高低饱和突变。
2) 油腻感 / 塑料感（greasy）：
   - AI 生成特有的"油光/塑料感"：皮肤/物体表面过度平滑、蜡质高光、糊成一层油膜、磨皮感过重、质感失真发假。

输出严格 JSON：
{
  "per_frame": [
    {"time": "00:03.0", "issue": "exposure_color|greasy|none", "severity": 0, "note": "具体证据"}
  ],
  "exposure_color": {"verdict": "violated|pass", "severity": 0, "evidence": "综合结论"},
  "greasy": {"verdict": "violated|pass", "severity": 0, "evidence": "综合结论"}
}

判定基准与尺度：
- 基准是"正常观看时能明显感到画面**画质不对劲/发假/发脏**"。severity：1轻微、2明显、3严重。
- 只要**有帧**明显出现上述问题，对应类别 verdict=violated，severity 取问题帧的最高值。
- **区分风格与缺陷**：导演意图的低调布光、暖调夕阳、冷调夜景、赛博霓虹、黑白/复古调色、水墨风等
  **本身的艺术风格不算异常**；只有"技术性画质坏了"（死白死黑、脏偏色、断层、油腻塑料感）才算 violated。
- 拿不准、只是风格化 → pass、severity=0。宁可放过风格，不要把正常调色误判为异常。
```

## 4. P0.3 文字异常（生成文字不可读）

- **判定入口**：`visual_text` 的 `verdict == violated`。
- **采样**：全片原生帧 ≤12（文字需分辨率，且可能任意时刻出现，覆盖要密）。
- **范围扩展（关键改动）**：不再只判"prompt 要求的文字"，而是**任何清晰醒目的生成文字**（字幕/招牌/UI/海报…）都判可读性。
- **当前表现**：P0.86 R0.82 F1 0.84（较优化前 R 55→82）；**误报** 023/028/032（把轻微字形/大小写差异判成不可读）。
- **已知问题 / 可提升点**：
  1. 误报来自"字形轻微不完美"与"真乱码"的边界——可要求模型区分"影响语义的乱码"vs"可辨认的轻微瑕疵"。
  2. 漏报 001/014/018/022：部分是文字很小/一闪而过，可能采样没覆盖到——可在"检测到有文字的帧"附近加密二次抽帧。
  3. 可引入 OCR 置信度作为辅助信号。

### System Prompt：`TEXT_SCAN_SYSTEM`
```
你是 Video Judge 的「生成文字可读性」专项判定器。

给你若干张来自同一视频、按时间顺序标注时刻的原生分辨率高清帧（覆盖全片）。只判断一件事：
**画面中由模型生成的、清晰可见的文字，是否存在"不可读 / 乱码 / 字形崩坏 / 明显拼写错乱"**。

考核范围（重要——比"prompt 是否要求文字"更宽）：
- **画面里任何醒目的生成文字都要判**：字幕、标题、招牌、标语、屏幕/UI、面板、包装、海报、弹幕等。
- 只要这些文字在画面中**清晰醒目**（不是远景里一小片背景噪点），就纳入可读性考核，
  **不要因为"prompt 没要求这段文字"就记 not_applicable 放过**。

判定"不可读"（violated）的情形：
- 字形扭曲/崩坏、笔画粘连错乱、不成字（火星文/乱码）；
- 明显的错字、缺笔多笔、字符拼贴成无意义串；外文单词字母错乱拼错。

输出严格 JSON：
{
  "per_frame": [
    {"time": "00:02.0", "readable": false, "text_seen": "看到的文字（或描述）", "note": "哪里不可读/怎么坏的"}
  ],
  "verdict": "violated|pass|not_applicable",
  "severity": 0,
  "evidence": "综合结论：哪一帧、什么文字、怎么坏的"
}

判定基准：
- 只要**有帧**出现清晰醒目却不可读/乱码/字形崩坏的生成文字 → verdict=violated，severity 记 2（明显）或 3（严重，大段乱码/核心文字全崩）。
- 全片**没有任何醒目生成文字** → verdict=not_applicable、severity=0。
- 有生成文字且都清晰正确可读 → verdict=pass、severity=0。
- **区分"不可读"与"看不清"**：因分辨率/远景/运动模糊导致的小字发糊，但字形本身没崩 → 不算 violated（pass 或 not_applicable）。
  只有字形**本身生成坏了**才算。轻微字体风格化、艺术字不算崩坏。
```

## 6. 共性可提升方向（跨维度）

1. **让模型直接输出 0-100 置信分**：当前是离散 verdict+severity，ROC 只有 3-4 个可切点、阈值不可细调。加连续置信分后可按业务偏好卡精度/召回、画平滑 ROC。
2. **程序辅助信号交叉**：曝光/颜色可用 ffmpeg 客观量化；文字可用 OCR 置信度；崩坏可用时序一致性/光流。程序信号与模型判断"双轨"更稳、可审计。
3. **采样自适应**：先粗判定位可疑时刻，再在其邻域加密二次抽帧（文字/崩坏尤其受益）。
4. **标签边界**：负例样本偏少（8~11），且部分"模型抠出的真实但亚显著瑕疵"与人工标准不一致（崩坏 025/026、文字 028 等）。建议扩负例 + 明确标注口径（是否算"明显"）。
5. **崩坏专项**：当前最弱（特异度 0.36），提升重点是"收误报但不砸召回"——主体显著度先验 / 时序确认 / 置信分阈值。
```
