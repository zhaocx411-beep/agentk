# Narrato 开场抓手与解说节奏设计

## 目标

自动生成的纪录片解说应在开场尽快给观众一个真实、由证据支持的抓手，并避免字幕长时间消失。默认目标是首条解说在 0–3 秒内开始；没有信息量人物对白需要保留时，相邻解说之间以及最后一条解说到片尾的空档通常不超过 5 秒。手工导入脚本仍只接受结构和时间轴校验，不把创作节奏升级为无法渲染的硬错误。

## 数据流与兜底

叙事策划提示词要求首个 `storyBeat` 覆盖开场并承载 hook。脚本提示词进一步要求 `cue-001` 在 3 秒内开始、直接实现 `narrativeProfile.hook`，并按 5 秒空档目标生成足够的 cue。生成结果通过软质量门检查：首条 cue 过晚，或非对白空档超过 5 秒时，最多复用现有预算进行两次修订。ASR 中的有效对白仍作为保守保护区，避免为了密度覆盖人物台词。

若三次模型输出后开场仍过晚，工作流会在 0 秒确定性补入策划 hook，并重新运行自动结构校验和 cue 编号归一化。其他仍未满足的节奏问题以 `pacingWarning` 随结果返回，继续允许渲染。模型完全不可用时，确定性 fallback 的第一条 cue 也从 0 秒开始并使用策划 hook。

工作流类型继续使用 `narrato.documentary.generate_script.v2`，并通过稳定的 Temporal patch ID `narrato-opening-cadence-2026-08-27` 选择节奏版本。没有该 marker 的旧 history 仍按原 18 秒重试阈值、原提示词和原 fallback 重放；新执行记录 marker 后才进入 3 秒/5 秒路径，避免滚动部署时破坏在途任务的确定性。

## 验证

测试覆盖提示词中的 3 秒/5 秒规则、阈值边界、修订提示、重试耗尽后的开场 hook 注入、fallback 开场、500 条 cue 上限、旧 history 分支以及原有对白保护。完整工作流测试同时确认渲染、TTS 和手工脚本契约不受影响。
