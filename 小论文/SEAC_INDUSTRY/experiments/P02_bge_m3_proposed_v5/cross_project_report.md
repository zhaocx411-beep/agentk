# Proposed v5 跨项目验证报告

## 实验设置

- P01：镔鑫智慧安全二期，32 个问答、人工复核前候选断点。
- P02：晋钢安全预警平台，36 个平衡问答、50 个候选断点。
- 编码器：BGE-M3，CPU，离线运行。
- 所有方法统一使用 `max_tokens=512`、`overlap=64`。
- Proposed v5 固定使用 P01 阶段确定的参数：`soft_target=320`、`dense_target=224`、`min_chunk=48`、`semantic_percentile=0.8`，未针对 P02 调参。
- P02 技术协议 PDF 为扫描件，未抽取出文字，本轮实验排除该文档。

## 分类型观察

- Semantic 在 P02 的 API 精确事实检索上表现最好：8 个 API 问题全部排名第 1。
- Proposed v5 在复杂问题上更稳：Constraint 的 MRR 为 0.246，Semantic 为 0.051；Feature 的 MRR 为 0.410，Semantic 为 0.202；Process 的 MRR 为 0.119，Semantic 接近 0。
- Proposed v5 的主要短板是数据库表和短事实的 Top-1 精确定位，导致 P02 的 MRR 和 Hit@1 未达到最优。
- Proposed v5 的 Hit@3 和 Hit@5 为 P02 最优，说明它更适合需要返回候选上下文供 RAG/人工阅读的场景。

## 结论

Proposed v5 具备跨项目可行性，但不能表述为在每个项目、每个指标上全面最优。更准确的论文结论是：

> Proposed v5 在两个项目上的平均综合表现最优，并在复杂约束、功能和流程问题及 Top-k 召回方面表现出明显优势；但对于短事实和 API 精确定位，纯语义切分仍可能取得更高的 Top-1 检索性能。

## 有效性限制

- P02 问答和断点标签仍为自动生成后的待人工复核版本，正式论文结果应在人工审核后重跑。
- P02 技术协议扫描 PDF 尚未 OCR。
- 当前只有两个项目，足以做初步泛化检查，但不足以支持强泛化结论。
