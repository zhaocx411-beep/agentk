# LLM 预标判定口径（v1.0）

本文件记录 `industrial-seac-llm-prelabel-v1.0` 实际执行的判定口径。它不替代
`docs/annotation_and_privacy_protocol.md` 第 4 节，而是把该节规则在本语料上的
歧义点固定下来，供人工验证阶段复核和推翻。

判断只回答一个问题：在不考虑算法预测、且长度允许的情况下，右侧单元是否应开始
一个新的、语义上可独立检索的父块。禁止因为文本接近 512 token 而判 `BREAK`。

## 一、判 NOISE 的情形

规程 §4.1 规定"左右任一单元主要是……空模板、无意义占位符、转换乱码或无法形成
内容证据的残片"即判 `NOISE`。在本语料中固定为：

1. 裸模板标签：单元全文仅为 `输入`／`输出`／`处理`／`处理逻辑`／`返回`／
   `返回信息`／`请求信息`／`新增`／`删除`／`查询` 等操作或字段标签，且不含任何
   取值、约束或说明。这类单元无法单独支撑任何问题的答案。
2. 目录导航：标题或段落尾部带页码（如 `3.18.1 功能描述 336`），或标题路径中
   夹带页码，表明该单元来自目录而非正文。
3. 页眉页脚、孤立页码、空单元格、纯占位符、转换乱码或字符高度重复的残片。

反例（不判 NOISE）：`POST`、接口方法名、字段名、`字符串：最大长度100个字符`
等短文本仍是有效证据。

## 二、判 NO_BREAK 的情形

1. 同一张表内：表头与数据行、相邻数据行，一律 `NO_BREAK`。行级检索由
   `gold_evidence_unit_id` 与 SEAC 子块处理，不通过父块边界拆表。
2. 标题锚定：标题与其首个内容单元 `NO_BREAK`；父标题与紧随的首个子标题也
   `NO_BREAK`，否则会产生纯标题碎片。
3. 引出关系：`请求路径：`／`返回信息参数：`／`成功返回信息：` 等引导句与其后的
   取值、报文体或表格 `NO_BREAK`。
4. 同一对象的相邻属性：同一接口、同一需求、同一画面、同一数据库表、同一流程的
   相邻属性或区域说明。
5. 论述延续：右侧是左侧句子、列表项、步骤、条件、示例的延续，含"其次""同时"
   等递进衔接。
6. 概述与其首个子项说明。

## 三、判 BREAK 的情形

1. 进入同级或更高层的新章节、新功能、新接口、新会议议题、新需求主题，且左侧
   主题已闭合。
2. 退出一张表后开始新的正文主题，或从正文进入一个新的独立表格。
3. 数据库设计中从第 n 张表的最后一行进入第 n+1 张表的表名行。
4. 同一大章节内左右应分别被检索返回，合并会明显混淆证据（如成功返回示例结束、
   开始失败返回说明）。

## 四、NEEDS_HUMAN_REVIEW 标记条件

预标结果附 `prelabel_flag`。满足任一条件即标 `NEEDS_HUMAN_REVIEW`，人工验证阶段
优先复核这些行：

1. 疑似转换缺失：左侧为裸页面名或裸标题，正文疑在转换中丢失。
2. 目录与正文难以区分的标题。
3. 封面元素之间的边界。
4. 引导句与表格的从属关系不确定，或表格归属不唯一。
5. 其他在两个标签间难以取舍的情形。

## 五、不确定时的默认

规程要求不得留空。难例仍给出最佳判断，并置
`prelabel_flag=NEEDS_HUMAN_REVIEW`，在 `prelabel_notes` 用一句话写明歧义来源。
